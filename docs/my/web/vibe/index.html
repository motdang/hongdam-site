သိထားသင့်သည်

  • Lovable သည် ပရောဂျက်တစ်ခုချင်းကို ၎င်းဖန်တီးပေးသော GitHub repository နှင့် ချိတ်ဆက်သည်။ Lovable တွင် ပြောင်းလဲမှုများ GitHub သို့ sync ဖြစ်ပြီး active branch သို့ push လုပ်သည်များ ပြန် sync ဖြစ်သည်။ repository ကို clone လုပ်၍ ကိုယ်နှစ်သက်ရာ editor တွင် ဆက်လုပ်နိုင်ပြီး ငွေပေးအစီအစဉ်များတွင် codebase ကို ဒေါင်းလုဒ်လုပ်နိုင်သည်။ docs.lovable.dev
  • Supabase ၏ စာမျက်နှာတွင် ဖွင့်ထားသော schema ရှိ table တစ်ခုကို row level security (RLS၊ table ၏ အတန်းတစ်ခုချင်းကို ဘယ်သူ ဖတ်/ပြင်နိုင်သည်ဟု သတ်မှတ်သော စည်းမျဉ်း) မဖွင့်ထားလျှင် grant ရထားသော role မည်သည့်အရာမဆို ဖတ်နိုင်၊ ရေးနိုင်သည်ဟု ဆိုသည်။ RLS ဖွင့်ပြီးနောက် policy များ မဖန်တီးမချင်း API သည် publishable key ကို ဒေတာ မပေးပါ။ supabase.com
  • Stripe ၏ စာမျက်နှာတွင် secret API key (ဆော့ဖ်ဝဲက Stripe အကောင့်ပေါ်တွင် လုပ်ဆောင်နိုင်စေသော ကုဒ်) များကို ဆာဗာဘက်ပတ်ဝန်းကျင်တွင် ထားရမည်ဖြစ်ပြီး source code ထဲ မထည့်ရ၊ အက်ပ်ထဲ မထည့်သွင်းရဟု ဆိုသည်။ publishable key များကို ဝက်ဘ်စာမျက်နှာနှင့် အက်ပ်များတွင် ထည့်ရန် ဘေးကင်းသည်။ docs.stripe.com
  • Aibrify ၏ Lovable အက်ပ်စာမျက်နှာတွင် ပြဿနာများကို စာရင်းပြုထားသည်။ ဖန်သားပြင်ဖြူနေခြင်း၊ ဝင်ရောက်မှုမအောင်မြင်ခြင်း၊ အသုံးပြုသူများက အခြားသူ၏ဒေတာကို မြင်ရခြင်း သို့မဟုတ် ပြောင်းလဲနိုင်ခြင်း၊ ထုတ်ဝေမှုမအောင်မြင်ခြင်း၊ ထုတ်ဝေပြီးအက်ပ်သည် preview နှင့် ကွဲပြားခြင်း၊ ဒေတာမသိမ်းခြင်း၊ row-level security မရှိသော table များ၊ ဆာဗာသက်သက်သုံး key များ ဘရောက်ဇာတွင် ပေါ်နေခြင်း တို့ဖြစ်သည်။ aibrify.com

row level security မဖွင့်ထားလျှင် မည်သူမဆို table ကို ဖတ်နိုင်သလား။

Supabase ၏ စာမျက်နှာတွင် ဖွင့်ထားသော schema ရှိ table တစ်ခုကို RLS မဖွင့်ထားလျှင် grant ရထားသော role မည်သည့်အရာမဆို ဖတ်နိုင်၊ ရေးနိုင်သည်ဟု ဆိုသည်။ RLS ဖွင့်ထားလျှင် policy များ မဖန်တီးမချင်း API သည် publishable key ကို ဒေတာ မပေးပါ။ supabase.com
